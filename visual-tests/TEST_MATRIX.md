# Next.js 全量视觉回归测试矩阵

## 目标与边界

视觉测试负责发现布局、颜色、字体、间距、遮挡、滚动和交互状态的回归；接口参数、
排序、权限判断和数据转换仍由 `src/**/*.test.ts` 单元测试负责。关键流程会同时做
DOM 断言与截图，避免“截图看着正常但功能不可用”。

全量覆盖不采用“每个页面 × 每种网络错误 × 每种屏幕”的笛卡尔积。采用以下规则控制
重复：

- 每个主要页面至少覆盖默认态和一种非默认态（空数据、加载或错误）。
- 每个异步功能域至少覆盖一次慢请求和一次失败。
- 每个写操作至少断言提交中、成功反馈和失败恢复，不一定三种状态都保存截图。
- 每个权限敏感入口至少覆盖“有权限可见”和“无权限隐藏”。
- 桌面端覆盖全部功能；窄屏只覆盖应用骨架、聊天和主要弹窗。
- 时间、用户、项目、会话和随机 ID 全部固定，禁止依赖真实后端数据。

## 目录与命名

```text
specs/
  normal/          # 默认页面、主要流程、空状态
  interaction/     # 弹窗、菜单、编辑、上传、流式回复
  permissions/     # 管理员、普通用户、只读用户
  resilience/      # 慢网、超时、4xx/5xx、离线、重试
  responsive/      # 窄屏和临界宽度
snapshots/
  <同 specs 分类>/<spec 文件>/<场景名>.png
```

场景使用稳定编号，例如 `CHAT-07-streaming-search`。测试标题、截图文件名和下面的
矩阵编号保持一致，便于从失败报告定位到产品功能。

## 实施批次

1. **P0 骨架与核心闭环**：AUTH、SHELL、CHAT、PROJECT、DOC 的 P0 场景。
2. **P0 业务闭环**：TASK、SKILL、SETTINGS 的 P0 场景。
3. **P1 完整交互**：弹窗、菜单、上传、权限和全部接口错误恢复。
4. **P2 稳定性**：窄屏、超长数据、慢速流式和临界滚动。

首轮目标约 55 张 P0 基线；完成 P1 后约 90 张。P2 只在确实存在独立视觉结构时新增
基线，其余使用 DOM、可见性和尺寸断言，避免维护大量内容重复的截图。

## 每个新增 case 的完成标准

- 使用统一 fixture 构造固定数据，不访问真实服务端。
- 截图前等待字体、动画、请求和滚动位置稳定。
- 关键按钮同时断言可见性、可用性和点击结果。
- 慢请求使用可控闸门，不使用固定长时间 `waitForTimeout`。
- 错误场景断言用户可理解的文案，不暴露服务端原始堆栈。
- 基线图片经过人工检查后再提交。
- 对应功能发生变更时，同一个提交中更新测试与基线。
