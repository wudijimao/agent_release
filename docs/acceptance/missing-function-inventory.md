# BioAgent 新 Next.js 功能缺失单

## 1. 文档基线与分类

- 检查日期：2026-07-23
- 主仓库基线：`67b2333`
- 范围：高保真原型已经表达、但正式 Next.js 尚未形成真实闭环的功能
- 明确排除：`packages/web` 独有功能不迁移，不进入本缺失单

缺失类型：

- **缺接口**：服务端没有满足当前产品页面所需的稳定契约。
- **接口已有，前端未接**：服务端与 shared 已具备主要契约，但 Next.js 没有正式路由或 Adapter 装配。
- **接口不可用**：路由存在，但依赖的邮件、模型、存储或外部服务目前不能完成真实结果。
- **缺需求细化**：高保真交互与现有服务端模型无法直接对应，需要产品先明确范围、权限或状态规则。
- **缺验收**：实现已存在，但真实破坏性写入或特定环境链路尚未验证。

优先级：

- `P0`：阻塞核心用户闭环或正式上线。
- `P1`：主要页面或高频能力不完整。
- `P2`：次要能力、运营能力或范围待确认页面。

## 2. P0 缺失

### AUTH-GAP-01 注册闭环

- 优先级：`P0`
- 类型：**接口已有，前端未接** + **接口不可用** + **缺需求细化**
- 当前状态：
  - 高保真 `RegisterPage` 已在共享 UI 中。
  - 服务端已有：
    - `POST /api/auth/email-verification/send`
    - `POST /api/auth/register`
  - shared 已有 `RegisterRequest` 和 `EmailVerificationSendResponse`。
  - 正式 Next.js 没有 `/register` 路由和注册 Adapter。
  - 服务端已说明验证码接口存在，但邮件目前实际发不出去。
- 缺失细节：
  - 邮件服务商、发件域名、失败重试和告警没有形成可用运行环境。
  - 需要确认注册必填姓名、实验室创建/邀请码加入的最终步骤。
  - 需要定义验证码频率、倒计时、过期、错误次数和账号枚举保护。
  - 注册成功后是直接登录、回登录页，还是继续实验室引导，需要明确。
- 完成标准：
  - 邮件真实可达。
  - Next.js 路由和 Adapter 接入。
  - 注册、验证码错误/过期、邮箱已存在、限流和成功后的会话行为均验收通过。

### AUTH-GAP-02 找回密码闭环

- 优先级：`P0`
- 类型：**接口已有，前端未接** + **接口不可用**
- 当前状态：
  - 高保真 `ForgotPasswordPage` 已在共享 UI 中。
  - 服务端已有：
    - `POST /api/auth/password-reset/send`
    - `POST /api/auth/password-reset/confirm`
  - shared 已有 `PasswordResetConfirmRequest`。
  - 正式 Next.js 没有 `/forgot-password` 路由和重置密码 Adapter。
  - 邮件验证码投递当前不可用。
- 缺失细节：
  - 发送验证码、确认新密码和完成后重新登录的正式接线。
  - 验证码过期、错误次数、重发间隔、密码强度和限流提示。
  - 防止通过错误信息枚举邮箱是否存在。
- 完成标准：真实邮箱可以收到验证码，用户可以设置新密码，并用新密码登录。

### PROJECT-GAP-01 项目文档上传、新建、详情与下载

- 优先级：`P0`
- 类型：**新建/导入/基础详情已完成** + **高级操作缺需求细化**
- 当前状态：
  - 项目详情能读取服务端已有的知识摘要。
  - “新建文档”已使用 Milkdown 编辑 Markdown，并通过 `POST /api/knowledge/wiki2/nodes` 原子创建知识节点并关联当前项目。
  - 新接口由服务端事务保证节点创建、项目知识根节点初始化和项目关联同时成功或同时失败。
  - “导入文档”已接入 Wiki2 预签名上传、对象存储直传、附件登记和后台识别任务，并为每个文件创建和关联项目知识节点。
  - 支持 TXT、Markdown、CSV、图片、PDF、DOCX、PPTX、XLSX、GenBank、FASTA 和 DNA 文件；旧版 DOC/PPT/XLS 不支持。
  - 项目文档卡片已使用 `kbNodeId` 接入 Wiki2 节点详情接口，首期展示正文、附件和索引状态。
  - 详情页已复用高保真原型的文档框架，并可进入 Milkdown 编辑器；保存通过 `PUT /api/knowledge/wiki2/nodes/:id` 更新正文、标题、版本和索引。
  - 高保真原型中的删除按钮和确认弹窗已接入 `DELETE /api/knowledge/wiki2/nodes/:id`，删除成功后刷新项目文档列表。
  - 附件可通过服务端鉴权文件地址打开；面包屑和子节点暂不展示。
- 缺失细节：
  - 导入失败后的重试、去重和删除。
  - 新建文档目前为一次保存，没有草稿、自动保存、版本发布和离开前未保存确认的产品规则。
  - 独立文档详情路由、附件失效链接提示和更丰富的文件内预览方式。
  - 当前新建文档固定归入 `knowledge / other`；其他分类和标签来源仍需细化。
- 完成标准：项目内能真实创建或导入文档、查看处理状态、打开详情并按权限下载/删除。

- 类型：**外部服务可用性** + **缺运维指标**
- 当前状态：前端错误、停止和对账逻辑已完成；历史验收出现过上游 HTTP 503 和长时间停留在“准备生成回复”。
- 缺失细节：
  - 模型提供方可用性、超时预算、重试策略和熔断。
  - 用户可见的阶段超时文案。
  - 请求成功率、首字延迟、完整响应时延和 503 告警。

## 6. 建议处理顺序

1. 先解决邮件真实投递，完成注册和找回密码。
2. 明确项目文档实体与接口，随后完成 Chat 项目上下文。
3. 完成 HTTPS、域名、镜像源、监控和新旧前端切换方案。
4. 使用已有接口完成任务详情/运行记录和 Skills 管理页。
5. 明确 AI 用量的用户、权限、统计口径和充值定义。
6. 再决定实验详情、序列比对助手和独立设置入口是否进入当前版本。
